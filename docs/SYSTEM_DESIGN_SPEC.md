## Problem Statement

Tansen Sangeet Mahavidyalaya (Gurugram, est. 1972) needs its V2 website rebuilt from scratch. The V1 design code was deliberately removed from this repo for a fresh A-to-Z rebuild; what remains is content data (`src/data/courses.ts`, `gallery.ts`, `site.ts`), brand/content images (`public/images/`), and a working static-export deploy pipeline (`deploy_v2.py` → cPanel → `tansengurugram.com/demo/`). The client wants a site that first showcases the institution's 50+ year brand legacy and then captures admission inquiries — built page-by-page, not as one big-bang launch.

## Demand Evidence

- The school has real, paying students and continuous admissions since 1972 (52+ years), ISO 9001:2008 certified, claims 1,00,000+ alumni.
- Celebrity visits (Saroj Khan, Ismail Darbar, Annu Kapoor, Marzi Pestonji, Shakti Kapoor) provide non-replicable social proof; images already curated in `public/images/celebs/`.
- **Zero measurement today:** no analytics, no Search Console verification confirmed, no inquiry-source tracking. All inquiries arrive via phone/WhatsApp/walk-in with no attribution. This gap makes day-of-launch measurement setup mandatory (deferred by owner decision until pre-launch).
- Landscape research (2026): AI Overviews appear in ~64% of searches; music-school queries are heavily affected. In India, parents message 3-4 academies on WhatsApp and the fastest detailed reply wins. Fee transparency converts; hidden fees lose visitors. Real recital media beats stock photos.

## Constraints

1. Static export (Next.js `output: 'export'`) deployed to cPanel shared hosting — no server-side features, no ISR; forms must be mailto/WhatsApp/nodemailer-via-external or deferred.
2. Performance budget: LCP < 2.5s on Indian 4G. ONE animation library (`motion`, already installed); gsap/lenis dropped or strictly limited. Hero slide 1 optimized (AVIF/WebP, preloaded); carousel autoplay must be pausable. Under static export `next/image` performs no optimization — set `images.unoptimized: true` and produce AVIF/WebP hero exports via a one-time sharp-based script (like the repo's earlier `process_images.py`) into `public/images/optimized/`.
3. DPDP Act 2023: minors' photos/videos need verifiable parental consent; privacy page + gallery consent note required.
4. Brand-first visual quality bar (client explicitly prioritized brand over lead-gen emphasis).
5. Page-by-page sequential build; each page complete + polished before next starts.
6. Analytics/tracking installed just before launch (owner decision), not during build — but slots/event-name contract reserved now.
7. Claims discipline: "India's largest Music & Dance School" H1 needs substantiation or softening ("One of India's largest") pending client confirmation. "Since 1972" is safely verifiable; the ISO certificate version must be verified — 9001:2008 is a withdrawn standard superseded by 9001:2015, so confirm which version the school currently holds and display exactly that.

## Approaches Considered

### Approach A: Blueprint-Faithful Sequential Build
Exact blueprint, no extra layers. Effort S / Risk Low. Fastest client-visible progress, zero scope debate — but no conversion surface, nav lacks Contact, launch-day analytics scramble, course cards without SEO depth.

### Approach B: Brand Shell + Conversion Spine (SELECTED)
Client blueprint as-is PLUS invisible conversion layer: sticky WhatsApp FAB with prefilled deep-link message, CTA band after courses grid, tel/WhatsApp links + NAP in header/footer, course detail template ×9 (unique H1, Course+FAQPage schema, fee range or fee-policy line, age groups, per-course WhatsApp CTA), FAQPage markup on rendered FAQs only, single animation lib, LCP budget, DPDP privacy page. Effort M / Risk Low-Med. ~1-2 days slower on Home than A; closes all subagent-flagged gaps.

### Approach C: Proof-Density Experience (rejected)
Living proof archive: parallax recital collage hero, interactive celebrity timeline, count-up stats, audio samples per course, lenis storytelling page. Effort L / Risk High — LCP >4s realistic on 4G, three animation libs, weeks of delayed conversion elements, heavy cPanel hosting cost. Portfolio value real, wrong tradeoff for current stage.

## Recommended Approach

**Approach B**, because it honors both locked premises (brand-first, page-by-page) while closing the conversion gap cheaply (~1-2 days). Every page ships complete: showcase sections per blueprint + spine elements (FAB, CTAs, NAP).

### Color Palette (client-defined, locked D14)

Client set the brand colors directly: **orange = primary/hero**, **sky blue = supportive**. Token system grounded in the monochrome charcoal logo (#1F282D range):

```css
@theme {
  --color-brand:      #EE6C1E;  /* vivid orange — hero accents, primary CTAs, active states */
  --color-brand-deep: #C75312;  /* hover/pressed; orange variant that carries white text (AA) */
  --color-brand-tint: #FDEADD;  /* soft section washes */
  --color-sky:        #3FA3DC;  /* supportive — secondary sections, links, info chips */
  --color-sky-deep:   #1D7FB8;  /* sky variant for buttons/badges with white text */
  --color-sky-tint:   #E4F2FC;
  --color-ink:        #17232A;  /* logo-derived charcoal — all body text */
  --color-paper:      #FBFAF7;  /* page background, warm neutral */
  --color-line:       rgba(23,35,42,.09);
}
```

Usage rules:
- **Hero:** full-bleed real imagery + subtle brand→sky gradient overlay; paper-white serif headline; primary CTA button in `brand` (ink text) or `brand-deep` (white text).
- Light sections alternate `paper` with `brand-tint`/`sky-tint` washes for rhythm — no heavy color blocks.
- Inverted showcase sections (courses grid) use `ink` background, `paper` text, `sky` accents.
- Trust bar + affiliation badges on `sky-tint`, ink text.
- WhatsApp FAB keeps WhatsApp green — platform recognition beats brand purity.
- Accessibility: white text only on `brand-deep` / `sky-deep` / `ink`; light variants (`brand`, `sky`, tints) always carry ink text. WCAG AA throughout.
