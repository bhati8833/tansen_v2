# Tansen v1 - Deployment & Debugging Status

**Date:** 2026-09-03

## 1. What was the Initial Problem?
* The user deployed the new Next.js project to the `public_html/tansengurugram` folder on cPanel.
* However, the live website `tansengurugram.com` was not loading the new site and instead went into an **infinite redirect loop** (`ERR_TOO_MANY_REDIRECTS`).
* The other site `jrnavyandhraschool.com` (and its `jr-wing` subfolder) also started experiencing errors during the debugging process.

## 2. Root Cause Analysis & Fixes Applied Today
### A. The Infinite Redirect Loop (Cloudflare vs cPanel)
* **Cause:** Cloudflare's SSL encryption mode for `tansengurugram.com` was set to **"Flexible"**. In Flexible mode, Cloudflare connects to the cPanel origin server over HTTP (Port 80). However, the cPanel server was forcing a redirect to HTTPS. This caused Cloudflare to keep redirecting the user in an endless loop.
* **Fix Applied:** We used the Cloudflare API to change the SSL mode for `tansengurugram.com` from "Flexible" to **"Full"**. This makes Cloudflare connect to cPanel over HTTPS.
* **Result:** The homepage (`https://tansengurugram.com/`) successfully started loading the new Next.js site! (`200 OK`).

### B. The jr-wing Project
* **Cause:** During debugging, some changes to the root `.htaccess` temporarily affected `jrnavyandhraschool.com`.
* **Status:** We verified that `jrnavyandhraschool.com` is now returning a healthy `200 OK`. The `jr-wing` project inside `public_html/jr-wing` is untouched and safe.

## 3. New Issue Discovered (Pending)
### Cloudflare 522 / 525 Errors on Subpages
* **Issue:** While the homepage works, if a user visits a subpage without a trailing slash (e.g., `https://tansengurugram.com/about`), Cloudflare throws a **522 Connection Timed Out** or **525 SSL Handshake Failed** error.
* **Why this happens:** 
  * The Next.js project is configured with `trailingSlash: true`. This means the `/about` route is exported as a folder containing an `index.html` file (`about/index.html`).
  * When Apache receives a request for `/about` (without a slash), it automatically tries to issue a 301 redirect to `/about/` (with a slash) using `mod_dir`.
  * For some reason, this specific redirect generated by the cPanel Apache server causes the SSL connection with Cloudflare's "Full" mode to drop or hang.
* **Note:** If you manually type the URL *with* the slash (`https://tansengurugram.com/about/`), it loads perfectly fine!

## 4. Next Steps (For the next session)
When we resume, we need to focus on fixing the 522/525 timeout issue for URLs without trailing slashes. Here are the potential solutions we will explore:

1. **Option A: Change Next.js Config (Recommended):** Set `trailingSlash: false` in `next.config.ts` and rebuild. This will generate `.html` files (like `about.html`) instead of folders, completely avoiding Apache's buggy directory redirect.
2. **Option B: Fix cPanel "Force HTTPS":** Try to disable "Force HTTPS" entirely inside the cPanel dashboard. If we disable it, we can switch Cloudflare back to "Flexible" mode, which never suffers from these 522/525 SSL handshake timeouts.
3. **Option C: Custom Apache Rewrite:** Write a stricter `.htaccess` rule that manually handles the trailing slash redirect before Apache's `mod_dir` can cause the timeout. (We attempted this today, but it needs further refinement).
